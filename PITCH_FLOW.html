🌊 HydroTwin — Pitch Flow & Architecture

Real-time Copernicus Sentinel EO + OpenMeteo weather → AWS Bedrock (Claude 3 Sonnet) → email + Discord alerts on every status transition, for 32 Bulgarian regions, every 30 minutes.

"NIMH delivers the warning. bg-ALERT delivers the alarm. HydroTwin delivers the decision."

🧠 2. The 8 Lambdas

#LambdaTriggerWhat it does
1🎯 /assessAPI GW POSTPulls live EO + weather, calls Claude, returns structured risk assessment
2📡 cronEventBridge rate(30 min)Re-runs /assess for all 32 regions, writes snapshots, fires alerts on transitions only
3✉️ /subscribeAPI GW POSTSaves to DDB, sends welcome email + Discord embed
4🔓 /unsubscribeAPI GW GET/POSTHMAC-signed one-click, idempotent delete
5📊 /statusAPI GW GETPre-computed snapshots for instant map paint
6💬 /chat-alertAPI GW POST"HydroSentry" Claude assistant — Q&A scoped to active alert
7🚧 /damsAPI GW GETMonitors 3 Bulgarian dams (Kardzhali · Studen Kladenets · Ivaylovgrad)
8📝 /reportsAPI GW POST/GETCitizen incident submissions + triage feed

⏰ 8. Cron Transition Alerts (the autonomous brain)

This is the part that runs while everyone sleeps — and it's the differentiator vs. a static dashboard.

flowchart TB
    Start(["⏰ EventBridge
rate(30 minutes)"])
    Loop{{"🔁 For each of 32 regions
(3 oblasts + 29 municipalities)"}}
    Prior["📖 Read prior status
from HydroTwinStatus"]
    Assess["🎯 Run assess_region
(Sentinel + OpenMeteo + Bedrock)"]
    Write["📸 Write new snapshot"]
    Decide{"❓ Status changed?"}
    Skip["💤 Silent — no fire"]
    Channel["📣 Fire shared Discord channel"]
    Subs["🔍 Scan subscribers WHERE region_id"]
    Fan{{"📬 For each subscriber"}}
    Email["✉️ Personalized alert email"]
    PerUser["💬 Per-user Discord webhook"]

    Start --> Loop
    Loop --> Prior
    Prior --> Assess
    Assess --> Write
    Write --> Decide
    Decide -- "SAFE → SAFE" --> Skip
    Decide -- "any transition" --> Channel
    Channel --> Subs
    Subs --> Fan
    Fan --> Email
    Fan --> PerUser

Transition matrix — when do we fire?

PriorNewAction
none (first run)SAFE💤 silent
none (first run)non-SAFE🔥 fire
SAFESAFE💤 silent
SAFEany non-SAFE🔥 fire (escalation)
non-SAFESAFE🔥 fire (recovery)
non-SAFEdifferent non-SAFE🔥 fire (re-grade)

🔓 9. Unsubscribe Flow (HMAC-signed, one-click)

sequenceDiagram
    participant Email as 📧 Alert email
    actor User
    participant FE as /unsubscribe page
    participant L as λ /unsubscribe
    participant DB as HydroTwinSubscriptions

    Note over Email: Footer link:
?e=user@x.com&r=pleven&t={hmac_token}
    User->>Email: 🖱️ Click "Unsubscribe"
    Email->>FE: GET /unsubscribe?e=...&r=...&t=...
    FE->>L: POST { e, r, t }
    L->>L: 🔐 verify HMAC-SHA256
(constant-time compare)
    alt Token valid
        L->>DB: DeleteItem (idempotent)
        L-->>FE: 200 unsubscribed
        FE-->>User: ✅ "You're unsubscribed"
    else Bad token
        L-->>FE: 400 invalid token
        FE-->>User: ❌ "Invalid or expired link"
    end
  • 🔐 Token = HMAC-SHA256(secret, "email|region_id")[:16] — unguessable, unforgeable
  • ⏱️ hmac.compare_digest() = constant-time compare, no timing oracle
  • ♻️ Delete is idempotent — clicking twice doesn't error
